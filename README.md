# NAITA Daily Diary Automation

This repository provides a Bun CLI and OpenTUI terminal wizard for preparing the
NAITA industrial-training daily diary for a student.

## Requirement

The original requirement is to automate two separate parts of the diary:

1. Collect and fill the student's personal and training information without an
   AI agent. A normal CLI is sufficient for this part.
2. Read the student's Git history, map commits to calendar dates, and fill the
   daily work entries. Before generating the diary, the student must be asked for
   authorized leave dates and medical-leave dates so those days are recorded
   correctly. Generated text should use Times New Roman consistently.

An agent such as Codex or Claude may optionally improve the wording of Git-based
work descriptions, but it does not control dates, absence classification, or PDF
placement. Those rules remain deterministic in the CLI.

## What we found in the supplied template

`Daily Diary.pdf` is a static eight-page A4 PDF. It has no usable AcroForm fields,
so the automation uses the original pages as backgrounds and overlays generated
text at calibrated coordinates. The source template is never modified.

| Pages | Template area | Automation behavior |
| --- | --- | --- |
| 1 | Daily Diary cover | Copied unchanged |
| 2 | Apprentice and training information | Filled from the student profile |
| 3 | Weekly ending date, location, and daily work table | Repeated once per training week and filled from the calendar/Git history |
| 4 | Details and notes of work carried out | Repeated once per training week and filled with a compact dated work record |
| 5 | Continuation page, trainee signature, and engineer/T.O. certification | Copied unchanged; signatures and certification remain blank |
| 6 | NAITA/University/Institution inspection report | Copied unchanged; official-only fields remain blank |
| 7 | Establishment progress report and leave counts | Copied unchanged; supervisor comments, signatures, and official leave counts remain blank |
| 8 | Final template page | Copied unchanged |

The output embeds `C:\Windows\Fonts\times.ttf` as a subsetted Times New Roman
font for all text generated by the tool. The original template's typography,
watermark, borders, headers, and footers remain part of the background.

## Install

Requirements:

- [Bun](https://bun.sh/) 1.3 or newer
- Git
- Times New Roman installed at `C:\Windows\Fonts\times.ttf` on Windows
- Codex or Claude CLI only if agent-assisted wording is desired

Install dependencies:

```powershell
bun install
```

## Guided OpenTUI workflow

Run:

```powershell
bun run start
```

The OpenTUI wizard collects the profile, training period, Git repository, leave
dates, medical dates, and optional writing-agent choice in one flow. Press Enter
to advance. Ctrl+C safely exits the terminal UI.

The profile is saved locally as `naita-diary.json`; it is ignored by Git because
it contains personal information.

## Scripted CLI workflow

Collect the student information once:

```powershell
bun run cli -- init
```

Generate the diary from a student repository:

```powershell
bun run cli -- generate --repo C:\path\to\student-project
```

The CLI asks for authorized leave and medical-leave dates before filling the
document. Dates may be comma-separated or inclusive ranges:

```text
2026-04-10, 2026-04-20..2026-04-22
```

The default output is `output\NAITA-Daily-Diary.pdf`.

## Git history and agent wording

Git commits are read with their short commit date, subject, and body. Commits are
grouped into Monday-Sunday weeks covering the configured training period. A day
is classified in this order:

1. Outside the training period
2. Authorized leave
3. Medical leave
4. Work day

On work days, commit subjects provide the deterministic baseline description. A
work day without a commit is marked `No Git work recorded.` so the output does not
silently claim work that cannot be evidenced by the repository.

For optional agent-assisted wording:

```powershell
bun run cli -- generate --repo C:\path\to\student-project --agent codex
bun run cli -- generate --repo C:\path\to\student-project --agent claude
```

Codex runs with a read-only sandbox and Claude runs with `claude -p`. The selected
agent receives only the collected per-day commit data and must return structured
JSON. The CLI applies the response only to work days and enforces length limits;
the agent cannot change dates, leave/medical status, or form coordinates.

Useful options:

```powershell
bun run cli -- generate --repo C:\project --leave 2026-04-10 --medical 2026-04-11
bun run cli -- generate --repo C:\project --agent-command "my-agent --json"
bun run cli -- generate --repo C:\project --dry-run
```

Use `bun run cli -- help` for the complete command reference.
